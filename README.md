# Wazuh SOC Analyst Home Lab

## Windows Brute-Force Detection & Security Monitoring

This project demonstrates the setup and operation of a Wazuh Security Information and Event Management (SIEM) home lab designed to simulate Tier 1 SOC Analyst responsibilities.

The lab uses a Wazuh server running on Ubuntu Server and a Windows 11 endpoint to generate, collect, analyze, and investigate Windows security events.

### Project Objectives

- Deploy and configure a Wazuh SIEM environment
- Connect and monitor a Windows 11 endpoint
- Collect Windows Security Event Logs
- Investigate failed Windows logon attempts (Event ID 4625)
- Detect repeated failed authentication attempts
- Create and test a custom Wazuh brute-force detection rule
- Analyze security alerts from a SOC analyst perspective
- Document the investigation and detection process

- ## Lab Architecture

The lab was built using Oracle VirtualBox and consists of a Wazuh SIEM server and a monitored Windows 11 endpoint.

## Security Events Investigated

During the lab, Windows security activity was intentionally generated on the monitored endpoint to simulate events that a Tier 1 SOC Analyst may investigate.

### Event ID 4720 - User Account Created

A local test account was created on the Windows 11 endpoint.

**Test Account:** `SOC-TestUser2`

Wazuh successfully detected the account creation activity.

**Wazuh Alert:**
- Rule Description: User account enabled or created
- Rule Level: 8
- Windows Event ID: 4720
- Target User: SOC-TestUser2

### Event ID 4732 - User Added to Administrators Group

The test account was added to the local Administrators group to simulate a privilege escalation-related event.

Wazuh generated a higher-severity alert for this activity.

**Wazuh Alert:**
- Rule Description: Administrators Group Changed
- Rule Level: 12
- Windows Event ID: 4732
- Account: SOC-TestUser2

### Event ID 4625 - Failed Logon

Multiple incorrect passwords were entered for `SOC-TestUser2` to simulate repeated failed authentication attempts.

Windows generated multiple Event ID 4625 records.

Initial Wazuh alerts identified individual failed logons with the following information:

- Rule Description: Logon Failure - Unknown user or bad password
- Rule Level: 5
- Target User: SOC-TestUser2
- Logon Type: 2
- Status: 0xc000006d
- SubStatus: 0xc000006a

The repeated failed logons were then used to develop and test a custom Wazuh correlation rule for brute-force detection.

## Custom Brute-Force Detection

After verifying that Windows generated Event ID 4625 for failed authentication attempts, a custom Wazuh correlation rule was created to detect multiple failed logons against the same user account.

The rule was added to the Wazuh manager's local rules configuration.

### Custom Wazuh Rule

```xml
<group name="windows,authentication,">
  <rule id="100002" level="12" frequency="5" timeframe="60">
    <if_matched_sid>60122</if_matched_sid>
    <same_field>win.eventdata.targetUserName</same_field>
    <description>Windows brute force detected - multiple failed logins for same user</description>
  </rule>
</group>
```

### Detection Logic

The custom rule monitors alerts generated by Wazuh rule `60122`, which detects Windows failed logon events including Event ID `4625`.

The correlation rule triggers when:

- 5 failed logon events occur
- Within 60 seconds
- Against the same Windows user account
- The resulting alert is assigned severity level 12

### Test Result

Five failed authentication attempts were intentionally generated against the Windows test account.

**Target Account:** `SOC-TestUser2`

The Wazuh dashboard successfully generated the custom alert:

**Windows brute force detected - multiple failed logins for same user**

This confirmed that the custom correlation rule was functioning as intended.

## SOC Analyst Investigation

After the brute-force alert was generated, the alert was reviewed in the Wazuh dashboard to determine what activity caused the detection.

### Investigation Process

1. Reviewed the custom brute-force alert in the Wazuh dashboard.
2. Identified the affected endpoint and target user account.
3. Examined the Windows authentication events associated with the alert.
4. Confirmed multiple Event ID 4625 failed logon events occurred within a short period.
5. Reviewed the username, logon type, failure reason, status, and substatus fields.
6. Correlated the individual failed logon alerts with the custom brute-force detection.
7. Verified that the activity was generated intentionally as part of the lab.

### Key Findings

- Target Account: `SOC-TestUser2`
- Windows Event ID: `4625`
- Logon Type: `2` (Interactive)
- Status: `0xc000006d`
- SubStatus: `0xc000006a`
- Individual Failed Logon Rule Level: `5`
- Custom Brute-Force Alert Level: `10`

The investigation confirmed that multiple invalid password attempts against the same Windows account triggered the custom Wazuh correlation rule.

### Analyst Assessment

**Classification:** True Positive - Authorized Security Test

The detection correctly identified behavior consistent with a brute-force authentication attempt. Because the failed logons were intentionally generated as part of the controlled SOC lab, the activity did not require containment.

In a production environment, similar activity would require additional investigation to determine the source of the authentication attempts, whether the targeted account was compromised, and whether escalation or containment actions were necessary.

- ## Lessons Learned

Building this lab provided practical experience with the workflow a SOC Analyst follows from event generation through detection and investigation.

Key lessons from the project include:

- Understanding how Windows Security events are generated and forwarded to a SIEM
- Learning how Wazuh processes Windows events using detection rules
- Troubleshooting situations where Windows generated events but Wazuh alerts were not immediately visible
- Understanding the difference between individual failed logon events and correlated brute-force activity
- Creating and validating a custom detection rule
- Using event fields such as usernames, logon types, status codes, and timestamps during an investigation
- Recognizing the importance of testing and validating detection logic before relying on it in a production environment
- Documenting investigation findings so another analyst can understand and reproduce the analysis

This project demonstrates an end-to-end security monitoring workflow using Wazuh and a Windows endpoint.
